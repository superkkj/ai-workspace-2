# 핏로그 첫 사용 개선 — 2026-11-18

기존 디자인과 질문→선택→후기 방향을 유지한다. 이 문서는 코드와 회귀 검사에서 확인한 문제를 정리한다. 실제 브라우저에서 확인하지 못한 흐름을 실사용 성공으로 기록하지 않는다.

## 확인한 문제와 선정 이유

| 문제와 재현 조건 | 영향 | 개선 |
| --- | --- | --- |
| 작성 폼의 입력이 컴포넌트 상태에만 있어 닫기·새로고침으로 사라짐 | 긴 질문·후기를 다시 작성해야 함 | 사용자·폼·대상별 탭 초안, 복구 안내, 명시적 정리 |
| 생성은 성공했는데 응답이 유실된 뒤 내용을 수정해 같은 ID로 재시도 | 새 입력이 무시되고 이전 기록을 저장 성공으로 표시할 수 있음 | 최초 요청값/ID 보존, 동일 요청 재확인, 서버 입력 충돌 확인 |
| 미확정 생성 재시도에서 인증 오류를 받으면 원래 ID를 폐기 | 다시 로그인한 뒤 새 ID로 중복 생성 가능 | 과거 미확정 시도와 최초 확정 실패를 구분 |
| 수정 응답 유실 사이 다른 창에서 기록을 바꾼 뒤 과거 내용을 재전송 | 최신 내용을 덮어쓸 수 있음 | 미확정 수정은 조회로 확인하고 다른 값이면 자동 재전송 중단 |
| 삭제 완료 뒤 응답 유실, 동일 삭제 재시도에서 404 | 이미 삭제됐는데 화면이 오류 상태에 머묾 | 소유자 조건 DELETE와 일관된 응답, 실제 타인 자료 보존 검증 |
| 같은 후기를 한 달 뒤 그대로 PUT | 작성 당시 사용 기간이 0일에서 30일로 변함 | 내용이 같은 후기 저장은 관찰일을 갱신하지 않음 |
| 예시→실제 글 이동에서 모드가 남고, 내 기록 탭은 새로고침 때 초기화 | 보던 위치·검색 조건을 잃음 | 전체 탐색 상태를 URL로 읽고 쓰기 |
| 질문과 다른 모델을 최종 선택한 뒤 그 모델명으로 검색 | 후기를 찾을 수 없음 | 최종 선택 브랜드·모델·후기까지 검색 |
| 신발 등록 뒤 질문 버튼과 기준 신발을 별도로 찾아야 함 | 첫 질문까지 불필요한 단계 | 저장 직후 및 카드에 ‘이 신발로 질문하기’ |

우선순위는 입력·저장 안전성, 기록 다시 찾기, 다음 행동 연결의 세 묶음이다. 모바일 상세 상단의 선택/후기 버튼은 작은 화면에서 다음 행동을 가까이 두려는 개선이며, 실제 휴대폰 화면에서 효과를 확인한 것은 아니다.

## 확인한 범위와 제한

- 서버와 프런트 작성자를 나누고 서로 다른 담당자가 변경 코드를 독립 검토했다. 사용 도구는 ChatGPT 작업자이며 Claude 실행으로 기록하지 않는다.
- 실제 SQL/API, 초안 저장소와 요청 helper, URL 상태 해석의 자동 회귀 검사를 사용한다. 개수와 최종 빌드·배포 결과는 저장소 루트 `docs/ai/CHECKS.md`를 기준으로 한다.
- 사용자가 로그인 시작을 허용한 뒤 보안 입력 절차를 진행했지만, Google 인증 페이지에 비활동으로 세션이 종료됐다는 문구가 표시됐다. 로그인 성공이나 운영 데이터 쓰기는 확인하지 못했다.
- 로컬 preview가 한때 실행됐지만 브라우저 연결은 `ERR_CONNECTION_REFUSED`였고, 종료 상태 확인 뒤 재시작했다. 실패한 탭의 재연결에는 브라우저 URL 정책 제한이 반환돼 추가 우회를 하지 않았다.
- 데스크톱·모바일 렌더링, 실제 계정 CRUD, 실제 네트워크 끊김과 가상 키보드 동작은 미검증이다. 운영에 테스트 자료를 작성한 사실도 없으므로 운영 테스트 자료 정리는 발생하지 않았다.
- 초안은 같은 탭의 임시 자료다. 다른 기기 동기화·탭 종료 뒤 복구를 보장하지 않는다. 이미 저장된 게시물은 서버에 남는다.
- 과거 기록의 최초 요청 해시는 null을 유지한다. 2026-11-19에는 새 클라이언트가 보내는 편집 기준값을 서버에서 단일 SQL 문의 조건으로 확인해 첫 수정 동시 충돌을 보완했다. 구버전 요청 호환성·ABA·실계정 사용은 여전히 미확인이다.
